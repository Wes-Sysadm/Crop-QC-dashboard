## Exact failure path

1. `BinsRunService.GetPageAsync` loads room ledger snapshots and calls
   `BuildAvailableInventoryOptionsAsync`; canonical mode dispatches to
   `BuildCanonicalRunOptionsAsync` in `BinsRunService.Canonical.cs`.
2. `InventoryEvidenceLoader` retains legacy ledger 2852 as
   `ReceiptAdminOverride`, invariant version 1, with no movement parent. Movement
   481 is `ReceiptLocationCorrection`, also without a recognized parent.
3. `InventoryCohortEvidence.Related` accepts parentless correction matches only
   for canonical version 3, exact timestamps and supported canonical kinds.
   This legacy movement was recorded about 57 ms after the override. It is
   valid legacy evidence, not a canonical version-3 event.
4. The recorded-custody adapter previously recognized audited
   `InventoryReclassification` pairs, but not this `LocationCorrection` format.
   It supplied no link for ledger 2852. `InventoryEventReplay` consequently
   reported the credit as missing a supported origin/exact incoming allocation.
5. Raw projections 129 do not balance authority 378. Untreated-pool proof does
   not accept an unlinked `ReceiptAdminOverride`. The resolver therefore returns
   `UnknownTreatment`, zero eligible availability and `IsOperable=false`.
   The authoritative quantity itself remains 378.
6. `CanonicalInventoryMessages.Blocker` turns that typed rejection into the
   reported generic identity/treatment message. `BuildCanonicalRunOptionsAsync`
   explicitly renders blocked quantity as zero. Its former binary label chose
   “Confirmed treatment” for **every state except Untreated**, including the
   synthetic Unknown placeholder. This was a second, independent display defect.
7. `Views/BinsRun/Index.cshtml` disables selection when `!option.IsAvailable`
   (or the room is sealed). `SaveCanonicalActualRunAsync` independently rejects
   `!r.IsOperable`. The executor then rechecks fingerprint, treatment, available
   quantity and origin inside its Serializable transaction. None is bypassed.

Classification: incomplete derived projection plus missing recognition of valid
historical custody in the canonical reader, with a misleading treatment label.
There is no supported claim of an inventory shortage, identity mismatch, missing
origin or applicable unrecorded treatment in the target room.

## Focused systemic correction

`InventoryEvidenceLoader.RecordedCustody.cs` recognizes a legacy location pair
only after validating the completed parent, unchanged receipt identity/quantity,
before/after locations, exact signed legs, operation keys, actor, audit snapshots,
and immutable movement coverage. It supplies an in-memory common parent for
those proven ledger/movement records. Recorded movement treatment allocations
remain intact, including mixed treatment; source-pool reconstruction cannot
substitute a different allocation. Evidence and failed proof inputs enter the
fingerprint so narrow commands and broader selectors agree and changes stale
prior selections. There are no database writes or new writer capabilities.

`BinsRunService.Canonical.cs` labels Unknown treatment as “Needs Review”. Proven
Untreated and Confirmed labels remain distinct. The writer continues to reject
unsupported quantity, treatment and stale submissions.

An aggregate production query found **two completed legacy location corrections
across two grower lots** using this format. That is a potential impact count,
not a claim that both lots currently have blocked inventory. No lot/room/quantity
special case was added, and the other lot was not investigated.
