# Production inventory diagnostic acknowledgments

EF migration `20260809151943_AddInventoryDiagnosticAcknowledgments` adds a read-only inventory-diagnostic acknowledgment ledger. Production has known EF migration-history drift, so this release uses the bounded PostgreSQL package in `scripts/postgresql` rather than running all pending EF migrations.

## Reviewed object state

The package owns one table, `InventoryDiagnosticAcknowledgments`, with exactly 16 columns. `Id` is a PostgreSQL `bigint GENERATED BY DEFAULT AS IDENTITY`. Text lengths, nullability, ordinal positions, and timestamp/boolean types match the EF migration. The table has:

- primary key `PK_InventoryDiagnosticAcknowledgments` on `Id`;
- unique index `IX_InventoryDiagnosticAck_Key` on `DiagnosticKey`;
- indexes `IX_InventoryDiagnosticAck_DismissedBy`, `IX_InventoryDiagnosticAck_ActiveAdjustment` (`IsActive`, `RoomInventoryAdjustmentId` in that order), `IX_InventoryDiagnosticAck_RestoredBy`, and `IX_InventoryDiagnosticAck_Adjustment`;
- `FK_InventoryDiagnosticAck_Adjustment` to `RoomInventoryAdjustments.Id` with `ON DELETE RESTRICT`;
- dismissed/restored user FKs to `Users.Id` with `ON DELETE SET NULL`.

No seed rows are required. A nonzero acknowledgment count is valid and must be preserved on repeat apply. The package does not insert, update, or repair `__EFMigrationsHistory`.

## Fail-closed states

Run `preflight-inventory-diagnostic-acknowledgments.sql` before any apply. It is read-only and accepts only:

- **State A — absent:** the table, named indexes, and named constraints are completely absent and the target migration is not recorded;
- **State B — complete:** the full table shape, PK, all five indexes, and all three FKs match exactly.

Any partial or incompatible state is **State C** and stops the release. Examples include an incorrect column type/length/nullability/identity, missing or reordered index, wrong uniqueness, wrong FK target/delete action, an extra target-table index or constraint, or a migration-history row whose table is absent. Do not manually patch around State C.

## Production procedure

1. Create and independently verify the normal fresh production backup, including Drive read-back, readable PostgreSQL dump, manifest/component hashes, persisted run record, and lease release.
2. Restore that exact package to disposable PostgreSQL 18.
3. Record `__EFMigrationsHistory` and protected operational fingerprints before rehearsal.
4. Run the read-only preflight and require State A or State B.
5. Run `apply-inventory-diagnostic-acknowledgments-schema.sql`. It reruns preflight, takes a transaction-scoped advisory lock, creates only the reviewed table/constraints/indexes when fully absent, and otherwise performs a no-op.
6. Run `verify-inventory-diagnostic-acknowledgments.sql` and require the exact object state.
7. Run apply and verify a second time. Existing acknowledgment rows and their identity values must remain unchanged.
8. Run `dotnet CropQc.Web.dll --verify-schema=20260809151943_AddInventoryDiagnosticAcknowledgments`; the reviewed full object-state count is `267`.
9. Run inventory readiness and compare all protected fingerprints and migration history to the pre-apply baseline.
10. Only in a separately authorized release window, deploy the exact eventual PR #184 merge SHA and require normal health and authenticated UI checks.
11. After deployment, administrators may deliberately dismiss reviewed historical warnings through the protected UI.

The compatibility package must not change receipts, QC samples, Grower Lots, room-ledger quantities, Room Inventory Adjustments, Bins Run, Actual Runs/revisions, transfers, End-of-Day Fill configuration/history, role authorization, employment, Gmail credentials, or backup configuration. Only the new empty acknowledgment table and its owned database objects are expected on first apply.

No acknowledgment or AuditLog row is seeded by the schema package. In particular, the six reviewed historical `NoParent` warnings for adjustment IDs 2-7 remain active until an administrator explicitly dismisses them. Presentation acknowledgment never changes the underlying readiness result: historical nonblocking warnings remain nonblocking, while current-format/blocking diagnostics remain ineligible for dismissal.

Disposable State C cases independently proved fail-closed behavior for a wrong column length, a missing composite index, and a foreign key changed from `RESTRICT` to `CASCADE`. The forced-failure setting raised after DDL and before commit; the transaction rolled back and left the target table absent.

A separate fresh PostgreSQL 18 database was migrated through EF. Both the EF-created table and compatibility-created table passed the exact verifier and 267-object gate. Their normalized catalog signatures matched exactly: columns `15e45b59a02c9d81ee94b94011026290`, indexes `71106f320c54a177459a7c3fa0b0a11a`, and PK/FKs `b7e1ff8403c17a164325e59251a5efdb`.

These fresh/upgrade/idempotency/parity/State-C/rollback cases are repeatable with `scripts/test-inventory-diagnostic-acknowledgments-production-schema.ps1`. The harness creates only explicitly prefixed disposable PostgreSQL 18 databases and removes its temporary container unless `-KeepContainer` is supplied.

The apply script contains a test-only custom PostgreSQL setting, `cropqc.test_force_inventory_diagnostic_ack_failure=on`, used on disposable databases to raise after DDL but before commit. This proves transactional rollback. It is unset during normal operation and does not weaken the production path.
